# 298. 실제 펜 지연·끊김·떨림

상태: **실물 시험 대기**. 사용자의 펜 실물 검증 보류 지시를 유지한다. 이 문서와 빈 JSON 양식은 실행 결과가 아니며 완료 근거로 사용하지 않는다.

현재 배포 실행 파일의 해시와 Native 형식은 양식의 referenceBuild에 기록했다. 실제 시험 시 사용한 빌드·장치·드라이버·OS·모니터·도구 설정을 다시 확인해 기록한다. 물리 픽셀·논리 좌표·문서 픽셀과 원시 입력·앱 계산·화면 표시의 측정값을 구분한다.

원본을 유지하는 새 로컬 시험 문서와 별도 저장 경로를 사용하고, 데이터 수집 방법과 관측 가능한 항목부터 정한다. 수집하지 못한 값은 미측정으로 남긴다. 단위 시험이나 합성 이벤트의 수치를 실물 값으로 옮겨 적지 않는다.

1. **slow-line** — 느린 직선·곡선의 입력 궤적과 보이는 획을 기록한다. 손 움직임의 잔차와 장치 자체의 떨림을 동일시하지 않는다.
2. **fast-line** — 빠른 선과 방향 전환에서 누락·불연속·끝점 차이를 기록한다.
3. **display-latency** — 영상 또는 외부 표시 측정의 시각 기준·프레임률·불확도를 명시하고 접촉→표시 지연의 분포를 기록한다.
4. **event-latency** — 이벤트 도착/계산/렌더/제출/표시 중 실제로 관측한 시점을 구분해 기록한다. 서로 다른 시계는 동기화 방법을 남긴다.
5. **long-session** — 정한 장시간 세션의 실제 시작/종료·획수·누락률·메모리 변화와 드라이버/장치 조건을 기록한다.
6. **driver-comparison** — 같은 브러시·배율·표시 장치·표본 조건에서 각 사용 가능한 백엔드/드라이버를 별도 시행한다.

294번의 CPU 엔진 시간과 작은 렌더 표본은 실제 펜→화면 지연이 아니다. 영상의 접촉/표시 시점과 이벤트 로그의 시간은 별도 열에 보존한다. 표본율은 드라이버 보고값인지 이벤트로 산출한 값인지 표시하고, 수집 방법이 없는 값은 null/미측정으로 남긴다.

기록 양식: [physical-298-template.json](physical-298-template.json). 모든 사례는 not_run이고 수치·장치명·시각·결과는 비워 두었다.

완료 판정은 실제 시행 자료를 연결한 뒤 한다. 각 사례의 관측값·기대값·오차/실패와 해당 빌드·환경을 남기고, 미지원 속성은 지원 여부와 안내를 명시한다. 저장 전후 문서와 필요한 영상/이벤트 기록의 로컬 경로·해시를 보존한다. 필수 사례의 실제 결과가 없으면 체크리스트를 체크하지 않는다.
