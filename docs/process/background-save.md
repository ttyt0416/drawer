# 백그라운드 저장과 로컬 복구 세대

Save in background…는 기존 저장 전 검사를 거쳐 현재 수정 상태를 고정하고 별도 실제 쓰기 스레드에서 자체 형식 저장·검증·원자 교체를 수행한다. 작업공간에서 한 쓰기 작업만 실행한다. 진행 중 겹친 저장은 재시도를 안내하고 거절하여 이전 저장이 새 저장을 덮는 순서를 만들지 않는다. 게시한 프로젝트 세대의 페이지를 개별 저장으로 덮지 않고 별도 이름 저장을 안내한다. 완료는 캡처한 논리 상태에만 저장 기준을 적용한다. 이후 추가 편집은 dirty로 남는다. 실패는 기준을 갱신하지 않고 기존 정상본과 현재 그림을 유지한다.

로컬 복구는5–3600초 또는1–10000 편집 수정 번호 간격으로 입력이 끝난 경계에서 상태를 고정하고 백그라운드 기록한다. 주기·수정 간격·2–32 보관 세대와 전체 바이트 예산은 로컬 설정에 저장한다. 파일 준비 중 추가 편집을 허용하며 캡처 버퍼의 알려진 비용을 현재 문서 작업 예산에서 예약한다. 쓰기 실패 때 이전 복구 세대를 유지한다. 데이터 이동과 종료는 진행 작업의 결과를 회수한 뒤 처리한다. 쓰기 중 문서 저장/버리기 결정은 완료 뒤 복구 색인에서 해당 문서를 제거한다.

프로젝트는 페이지 순서·제본·제목과 열린 페이지의 고정 상태, 닫힌 페이지의 검증된 바이트를 같은 복구 세대에 저장한다. 페이지 위치는 세대 내부 상대 위치로 봉인하고 읽을 때 안전한 로컬 경로로 복원하므로 scratch 이동 후에도 유효하다. 복구 선택에서 별도 미저장 프로젝트로 연다. 지연 열기한 페이지도 원래 복구 파일을 덮지 않는 별도 미저장 문서다. 복구 프로젝트가 참조하는 세션은 새 로컬 프로젝트로 저장하기 전 삭제를 거절한다. 미저장 프로젝트 구조가 있으면 정상 종료에도 복구를 보존한다.

새 복구 세대는 전체 파일 목록/길이/SHA256을 동기화하여 봉인한다. 현재 색인과 정상 이전 색인이 참조하는 세대 및 설정한 최신 세대는 보관한다. 오래된 세대는 소유 세션 범위·링크 없음·전체 파일 목록/해시 일치 때만 정리한다. 알 수 없는/바뀐 파일과 과거 미해결 세션은 자동 삭제하지 않는다. 복구 색인2는 프로젝트를 포함하며 기존1도 읽는다. 문서 Native125 형식과 독립적이다.

검증: 멈춘 실제 저장 스레드 중 추가 편집·겹친 요청 거절·구 캡처만 저장/새 편집 dirty·다음 최신 저장·실제 공유 잠금 실패·명령/시간 간격·재시작·프로젝트 순서/메타데이터/열린 페이지의 같은 세대·보관2세대·알 수 없는 파일 유지·복구 프로젝트의 지연 페이지/삭제 보호. 실제 강제 종료 복구 회귀 시험도 유지한다. 한도 밖 큰 프로젝트는 이전 복구를 유지하며 명시적으로 거절한다.
