# 202 — 2D 카메라와 화면 전용 경로

`camera-2d` 명령에서 최종 카메라 적용을 켜고 기존 키 편집기로 위치·축별 양수 배율·각도·회전 중심 및 고정/선형/베지어 곡선을 편집한다. 최초 활성은 현재 프레임의 단위 자세와 캔버스 중심을 사용한다. 기존 199 부모 카메라가 있으면 그 값을 보존한다. 키 비활성은 현재 자세를 유지하고 키를 보존하며, 최종 카메라 적용 해제는 키를 지우지 않는다. 카메라 개체와 키/적용 여부는 그림 Undo/Redo와 변경 상태를 사용한다.

## 좌표와 합성

카메라 자세는 촬영 프레임의 로컬 좌표를 월드 좌표로 옮긴다. X/Y를 증가시키면 촬영 프레임이 오른쪽/아래로 움직여 화면의 고정 피사체는 반대쪽으로 움직인다. 배율1은 원래 크기, 배율2는 두 배 넓은 영역, 배율0.5는 두 배 확대다. 축별 확대율은1/배율이다. 양수 회전은 화면 좌표계의 시계 방향이다. 기존 Pose 한도(배율0.01..1000, 유한 좌표/각도)와 최대10000키를 유지한다. 범위 밖 평가는 양끝 키로 고정한다. 최종 카메라는 위치·크기·회전/중심을 적용하며 카메라 트랙의 불투명도는 기존 부모 연결의 속성으로만 사용한다.

모든 층/벡터/개체/폴더/셀 합성에 최종 역카메라를 한 번 적용한다. 출력 캔버스 경계를 먼저 검사한 뒤 월드를 샘플하므로 저장된 캔버스 밖 배치 래스터도 촬영 범위에 들어올 수 있다. 소스 픽셀을 굽지 않고 기존 부동소수점 합성/샘플링 정책을 사용한다. 부모 카메라에 연결된 층은 월드에서 카메라와 함께 움직여 최종 화면에서는 고정된다. 기존 부모 기능은 변경하지 않는다. 선택 경계와 어니언 소스 검사도 동일한 표시 좌표를 사용한다.

카메라 보기에서 그림 입력은 막되 보기 확대·이동·회전·반전은 허용한다. `Edit source content`로 기저 좌표의 편집 보기를 열고 `Return to camera view`로 돌아간다. Core도 카메라 보기의 소스 픽셀/배치·새 소스·벡터/개체/셀 내용 변경을 거절한다. 기저 내용 보기는 세션 상태이며 파일/그림 Undo에 포함하지 않는다. PNG 및 애니메이션 출력은 기저 보기에서도 항상 최종 카메라를 적용한다.

## 경로 가이드

문서별 표시 설정은 카메라 경로, 선택한 편집층 경로, 첫/끝 포함 범위, 키만/모든 프레임, 시작/끝 RGB, 모서리/회전 중심 연결선이다. 촬영 사각형과 이동 경로를 현재 카메라 보기로 투영하고 기존 캔버스 보기 변환으로 화면에 그린다. 색은 키 순번이 아니라 프레임 시간에 비례한다. 키만 보기는 관련 층/부모/카메라 키를 사용하고 셀 트랙의 노출 변경도 포함한다. 정지/한 키는 한 가이드를 표시한다. 삭제된 편집층은 건너뛰고 출력 픽셀은 유지한다.

모든 프레임은 경로당10000개, 카메라+편집층 합계20000개 사각형까지다. 소스 경계는 안정 ID별 한 번 계산하고 문서/수정/프레임/내용 보기/설정이 바뀔 때만 경로를 다시 계산한다. 도형은 화면에 직접 그리며 문서 렌더러·PNG·연속 PNG/APNG에는 포함하지 않는다. 어니언/라이트 테이블도 기존 화면 오버레이 규칙을 유지한다.

## 저장과 검증

native101은 Scene.keyframes의 camera_output과 선택적인 camera_guides를 저장한다. 기본 적용 false/기본 가이드는 생략한다. 가이드는 읽을 때 Document의 보기 설정으로 옮기고 그림 Snapshot 밖에서 관리한다. 보기 변경은 변경 표시·수정 번호·그림 Undo를 만들지 않고 명시 저장 시 문서에 포함한다. 이전 버전 헤더에 새 카메라/가이드가 있으면 거절한다. 별도 이미지 페이로드/의존성 추가는 없다.

검증은 카메라 이동·확대·90도 회전·부모 상쇄·양끝 고정·고정/선형/베지어·0배율 거절·실제 소스 보호/기저 보기·저장 재열기·구버전 위장·선택 경계·캔버스 밖 소스·정지/한 키/10000프레임·시간별 색·반전/회전/확대 좌표·어니언·실제 PNG 및 연속 PNG의 가이드 미출력을 검사한다. 앱 검증은 포인터 활성/표시/내용 보기/키 편집 연결, 카메라 보기의 획 차단과 마우스 확대를 사용한다. 실물 펜 검증은 보류한다.

회귀 검사에서 Windows PDF API의 DIP 출력이16×24 요청에서22×34 픽셀을 반환하는 기존 실패를 재현했다. 문서 출력 DPI를 화면 배율과 분리하기 위해 균일 배율/축당1픽셀 반올림 오차만 허용하고 Lanczos3으로 요청 픽셀 격자에 맞춘다. 처리 메모리 예산과100/125/140/150/175/200/300/500% 모의 배율, 실제 Windows PDF 선택/DPI/색/투명도 검사를 사용한다. API 단위는 [Microsoft 문서](https://learn.microsoft.com/en-us/uwp/api/windows.data.pdf.pdfpagerenderoptions.destinationwidth)에 따른다.
