# 247 — Independent JPEG quality, sampling and actual compression readback

The adapter pins jpeg-encoder0.7.1 with std only, without its optional unsafe SIMD feature. It exposes baseline sequential RGB8, independent luma/chroma quality1..100 and4:4:4/4:2:2/4:2:0. Alpha is composited in output RGB before conversion to JPEG components. DPI uses the existing rounded JFIF integer policy and exact selected ICC bytes are chunked through the encoder. The bounded writer checks cancellation and output byte limits during encoding. Input dimensions remain at most32768 and4M pixels; codec, ICC, decode and preview-copy memory are checked against available workspace.

Separate quality values scale separate Annex K example quantization tables with the libjpeg-style quality curve, clamped to baseline8bit table values. These are application quality settings, not standardized perceptual ratings. At1 all divisors clamp255 and at100 all become1. Independent parsing of actual DQT and SOF0 headers verifies the tables and component sampling. Changing one quality must leave the other component table unchanged.

An immutable encoded plan owns the reviewed bytes and source id/revision/frame/options. Its thumbnail reads the actual JPEG using the existing independent image/zune decoder, then converts decoded output RGB to display sRGB. It never substitutes a simulated pre-compression source thumbnail. Stored dimensions and decoder limits are checked, including odd17×9 edges. The still-image writer borrows the exact cached bytes and retains the common source/path/replace/cancel/atomic-output guards. Output-batch decodes its already prepared bytes and publishes the same bytes.

The app maintains one owned preview worker, rejects stale option results and clears confirmation on option changes. Initial composite preparation is independent of chosen format and is not canceled just by changing formats. Closing/reopening cancels and joins the old owned worker before releasing its snapshots. Failed compression is not automatically retried forever; Retry starts another attempt. Lossless formats keep their direct exact prepared-channel preview. Unsupported progressive, arithmetic and arbitrary-table UI controls explain that this adapter validates baseline only.

Verification covers both quality endpoints and asymmetric quality pairs under all three samplings, independent header/decoder checks, colored thin-edge fixtures, alpha matte, exact cached-file bytes, deterministic re-encoding, non-sRGB proof readback, source state/bytes guards, cancellation and stale settings. Pointer replay switches sampling, checks reconfirmation/re-encoding and exact file bytes, then cancels another output. Installation smoke repeats the checks.

Primary references: [jpeg-encoder0.7.1 API](https://docs.rs/jpeg-encoder/0.7.1/jpeg_encoder/struct.Encoder.html), [upstream source and licenses](https://github.com/vstroebel/jpeg-encoder), and [ITU-T T.81, Annex K example tables / Annex B headers](https://www.w3.org/Graphics/JPEG/itu-t81.pdf). No private drawing-program code is used. The dependency and all bundled license texts are recorded in the lockfile and generated component notices.
