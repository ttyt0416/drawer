# Direct touch, gestures and palm policy (050)

The Windows adapter reads only our root's WM_TOUCH with GetTouchInputInfo. winit already registers this window with TWF_WANTPALM. A local subclass copies the bounded batch before the original procedure runs, forwards the original arguments exactly once through DefSubclassProc, and never closes the borrowed HTOUCHINPUT: winit owns its final CloseTouchInputHandle. Source hSource/dwID, signed hundredths-of-screen-pixel coordinates, explicit stylus/palm flags and an adapter-generated native batch ID are preserved. Stylus-flagged touch is not interpreted as a finger. Coalesced positions in one native message remain one batch; no time/proximity identity guess occurs.

The callback context is an owned stable Box of Weak<RefCell<State>> on the UI thread. Rc prevents thread migration and Weak prevents a window/state ownership cycle. Reentry forwards messages without borrowing busy state. Subclass removal precedes the retained root window's release. If Windows declines removal while a window is still alive, the small Weak allocation is retained until process exit to prevent a dangling callback; no event pointers cross the private OS boundary. GetTouchInputInfo errors, oversized batches or queue overflow cancel pending input. The adapter retains at most 32 native contacts, reads at most 256 structures per batch and shares the existing 65536-event queue. It does not hook other applications or inject input.

Local settings default to gestures on, finger drawing off and rejection of OS-marked palms on. Only identified touch is accepted. The original UI still receives touch clicks, while OS touch-compatible mouse copies cannot become a second drawing or gesture contact. Pressure absence is full-pressure fallback, not a device classifier. Physical-pixel offsets from item 048 are applied before touch policy.

Two accepted contacts from the same device manipulate the view. Their midpoint anchors a document point, separation changes zoom and vector angle changes rotation; final translation preserves that document point under the new midpoint across receiving DPI, view rotation and mirror. Zoom/pan obey the established view limits. Nearly coincident points pan without unstable scale/rotation. More than two fingers pause manipulation; finger-count/identity changes rebase rather than jump. Native batched positions are applied together, avoiding a false intermediate pinch/rotation from processing one finger first.

The first touch must start in the active drawing viewport and its actual UI layer. Contacts begun over another panel or text field remain blocked until release. View/geometry/scale/settings changes cancel a finger preview and block held contacts until lift. Known pen contact (including pressure below an application click threshold) always suppresses touch and cancels pending finger ink. Mouse drawing also takes priority. OS-marked palms are separately tracked for rejection and prevention of legacy canvas drag side effects. Unknown touch is not promoted to pen/finger by pressure. Original pointer UI view drags are suppressed for touch, so one native gesture cannot also pan through its mouse copy.

Explicit single-finger drawing uses the normal brush, pending preview, ownership and one-entry undo pipeline. A second finger cancels that uncommitted ink before beginning a gesture. Returning to one finger never synthesizes a new Down. A gesture is an ordered canvas input effect, not a pre-frame transform: a completed stroke before it is committed using its old view, and a following stroke uses the new view. Gesture changes affect only View and do not dirty pixels, native document state or edit history. Focus loss cancels pending ink and all contact/priority state even while a settings window is open. New contact after focus regain works; held moves do not restart drawing.

Synthetic tests cover batched midpoint/scale/angle, receiving DPI and mirror/rotation, coincident points, two/three/one finger transitions, source isolation, UI rejection, pen priority, palms, promotion suppression, settings and focus reset, signed native coordinate decoding, real application view-only behavior, finger preview cancellation, fresh finger stroke and Undo/Redo. Packaged smoke also confirms the adapter attaches to its own window; it does not generate physical touch. Actual tablet/touchscreen/palm-driver behavior and latency remain unverified. This adapter consumes Windows direct touch exposed through WM_TOUCH; no unsupported touchpad/driver gesture is inferred.
