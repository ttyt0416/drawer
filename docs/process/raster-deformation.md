# Raster deformation — checklist154

Four-corner free deformation uses an invertible bilinear quadrilateral; Perspective uses a projective homography. Corners are normalized against the common bounds of chosen raster layers, intersected with the selected-pixel bounds when requested. The pad maps the page to its displayed rectangle; numeric coordinates permit off-page corners. Reversed, concave, folded, degenerate, nonfinite or horizon-crossing quadrilaterals are rejected. Existing material/vector deformation remains available through the material transform command.

Liquify supplies Push, Expand, Pinch, Push Left, Push Right, Twirl Clockwise and Twirl Anti-Clockwise. Left/right are relative to drag travel in screen coordinates. Brush support is a radius0.5–1024 document-pixel disk with squared smooth falloff and strength0–1. Translation per dab is capped at a quarter radius. Expand/pinch use exponential radial resampling; twirl preserves distance to the center. Pointer segments are subdivided at a quarter-radius spacing, up to64 per event. A stationary drag starts one dab. Brush settings are captured per dab; later changes affect later dabs. A draft holds up to512 dabs. Stroke boundaries allow removing the last draft stroke; Escape/close discards all strokes.

Every dab reads the previous result separately in each target layer. All targets share the same document coordinates and original editing bounds. The target list includes linked raster transform members. A hidden, pixel/position locked, adjustment, alpha-protected or non-raster linked member rejects the whole operation before mutation. Explicitly convert non-raster sources or unlock their protected content before deforming. Layer masks, textures and rulers remain fixed in document space for these baked pixel edits.

Selected-pixel quad transforms cut the original selected coverage, inverse-sample it into the destination and carry the area selection along. Liquify keeps the selection fixed and mixes changes by its coverage. With Only refer to editing area, liquify reference samples outside common editing bounds or selected coverage are transparent; disabling it allows reading unselected source ink while still protecting pixels outside the selection. Empty selections do nothing. Pixels beyond the canvas are retained in bounded raster placements. Untouched pixels retain their native storage, including hidden8-bit RGB.

Native8/16-bit RGB and alpha are bilinearly sampled with premultiplied alpha, then stored with the document depth/dither/profile. Strength0 and identity quads return the exact snapshot, preserving dirty state and Undo/Redo. Output is limited to4M pixels per layer,32768 per axis,32M processing steps across layer/dab passes and4×4 selection samples, and document/workspace/Undo budgets. Large workloads fail before buffer allocation. Repeated dabs are intentionally baked sequentially; native storage rounding occurs between dabs.

The UI stores prepared pixels outside the document. Preview completion checks page id/revision/frame; failed preparation clears the previous plan. Apply commits the batch as one Undo. Save/Save As/direct app save show an unconfirmed-deformation message until Apply or Cancel, and do not create or overwrite a file. Only confirmed native pixel/placement data is serialized (existingv68 format). Physical pen-device verification is deferred; mouse input is covered by CPU-only UI replay.

Verification includes an independent exact translation reference and projective midpoint, all seven analytic sampling directions, folded/reversed/degenerate rejection, selected coverage and carried selection, transparent hidden RGB, zero strength, editing-area reference exclusion, multi-layer sequential equivalence,16-bit preservation, native reopen, atomic Undo/Redo, locked members and processing limits. App replay exercises mouse preview/apply, pointer-drag liquify with automatic preview, accumulated-draft Escape, Save notice/no file, stale frame, invalid-preview invalidation and zero-strength history preservation.
