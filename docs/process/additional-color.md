# Native RGB correction — checklist156

Levels maps the increasing input black/white interval into increasing output black/white values (0–1), with midtone gamma0.01–10. Values outside the input interval clamp to its endpoints. Color balance adds separate cyan/red, magenta/green and yellow/blue offsets(−1–1). Posterize rounds each component into2–256 equally spaced levels. Threshold uses0.2126R+0.7152G+0.0722B on the current document RGB values; components at/above the0–1 threshold become white, others black. Invert maps every component to1−value. These are explicit point operations in document RGB, with no display-sRGB conversion stage.

Pixel corrections preserve the original alpha, placement, document profile and8/16-bit precision. Pixels with zero alpha retain stored hidden colors. Selection strength mixes the corrected RGB with the source; pixels outside it remain byte-identical. Layer masks stay fixed and continue to control visible coverage. Identity levels/zero balance return the exact snapshot, preserving dirty/Undo/Redo. There is a4M source-pixel and document/workspace/Undo limit.

Layers commands open one correction dialog, with mode selection and before/after previews. Save while the dialog is unconfirmed writes the original document. Apply stores one Undo; Escape/close discards it. Changing page/revision/frame/target rejects stale application. Failed preparation clears an older prepared result. Parameters of these pixel operations are temporary; confirmed pixels are saved.

Inversion correction layer creates a nondestructive Adjustment with invert=true. Existing Color correction layers controls expose its inversion checkbox and can edit it. Ordinary brightness/contrast/HSL/HSV is applied first using existing semantics, then inversion operates in the document RGB working values. A pure inversion bypasses unnecessary profile round trips. Existing correction masks, layer opacity, clipping and folder composition limit its effect while retaining backdrop alpha and source pixels.

Nativev69 adds an optional invert boolean to correction-layer JSON. Missing/false means no inversion; false is omitted. Readers reject an active inversion under a header older than69 and still open v68 documents without it. Pixel/precision streams are unchanged. The main native-format document describes the boundary.

Profile assignment preserves source numbers and inversion parameters, so its appearance follows the newly assigned RGB space. Profile conversion with live correction layers requires the existing explicit current-frame rasterization option: the visible corrected composite is baked before converting, preserving that appearance while removing the original editable layers/hidden content as explained in the dialog. One Undo restores them. For already-baked pixel inversion, profile conversion follows ordinary stored-source color conversion.
