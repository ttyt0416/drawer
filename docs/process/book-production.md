# Local book production contract

The book-production command provides a perspective preview with textured local pages, cover IDs, physical spine width, opening, yaw and pitch. The project remains the authority for stable page IDs, reading order, binding and first side. Unpaired cover/end-page slots are blank. Only the current spread or selected cover textures are held. Preview preparation copies live unsaved states and loads closed native pages on a cancellable joined worker; later live/file/project changes require preparation again. The preview does not deform drawing sources or simulate paper/press mechanics.

Book setup v1 (.drawer-book, JSON,16KiB) stores front/back stable IDs, spine millimetres, minimum DPI/bleed/safe margins and optional expected trim. Save uses a new local filename, synchronized temporary output and no-overwrite publication. Load validates its version and finite ranges; cover references are checked against the current project. The same setup travels inside the storyboard. It is saved explicitly, separately from native drawing Undo.

Preflight checks invalid page/trim geometry, requested physical trim, document resolution, maximum-singular-value resolution of affine material and cached linked images and dialogue bounds against safe areas. Raster resolution is the page DPI; vector/text bounds are conservative. Nonlinear material warps require explicit resolution review. Findings are capped at4096 while retaining blocking status. Resolution, bleed and safe-area warnings require review. Invalid trim/reference errors block the checked PDF boundary even after acknowledgement. The checked PDF action reruns preflight on the prepared snapshot, preserves each page DPI and publishes only after composing every page. Other PDF/raster import/export commands retain their independent documented contracts; physical print proofs remain unverified.

Drawer storyboard v1 (.drawer-storyboard) is bounded versioned JSON with title, page IDs in reading order, binding/start-side, setup, complete editable existing frame/text objects keyed by stable source IDs, and hashed local native and PNG-preview paths. Export stages independent native snapshots and at-most256px previews in an exclusively created local resource directory, then publishes the JSON last. References are relative to its parent folder; move the JSON and its resource folder together. Import verifies every local reference/hash, decodes the real images/native sources within memory limits, rejects duplicate/missing IDs or changed object kinds, applies existing dialogue/frame edits, refreshes compound frame outlines and validates the complete scene. It supports editing existing exchanged objects, not inventing arbitrary source references. Unknown versions, omitted objects, path escape/network/unknown proprietary formats and malformed data fail before opening a project. Confirming opens a separate project with preserved exchanged IDs; existing documents and source files remain. Save that project explicitly in Page manager. No external proprietary storyboard adapter is claimed.

Continuous scan uses the existing selected local WIA scanner through an isolated helper process. Device enumeration is explicit. Each acquisition shows its slot/result; a failure pauses the slot for retry, skip or abort. DPI is the user-confirmed scan setting, not an assertion that a driver reported it. The complete reviewed batch is published to new local native pages with original encoded scan bytes and scans.json, then added atomically with one project Undo/Redo. Undo removes memberships and preserves permanent resources for Redo. A changed project, cancellation or resource failure never mutates original files. Preparation/publication use cancellable joined workers and owning resource guards. Raw originals stay beside the acquisition resources; native pages contain the decoded raster independently. Save the resulting project snapshot explicitly. A batch is limited to512 slots, the project to512 pages, each original to64MiB and the normal aggregate document budget. WIA capture is sequential and may show the scanner driver dialog; feeder automation is not claimed.

Verification uses generated local drawing/image data and MOCK scan results, never an attached scanner or actual paper. It covers blank/cover/odd spreads under both bindings/first sides, perspective geometry/depth, affine-shear DPI and nonlinear review, distinct missing-path rejection, physical preflight and checked-output gates, setup and storyboard round trips/edited dialogue, missing references/version/duplicate IDs/budgets, late publication failure and cancellation cleanup, source preservation, three acquisitions with the second failing, retry/skip/abort, exact original scan bytes, native reopen and one project Undo/Redo. App verification also exercises live source freshness, texture binding, and pointer confirmation of independent storyboard opening and mock scan-batch insertion. Physical scanner and pen verification remain deferred.

Preview supports page dimensions0.01..10000mm and width/height ratio0.05..20; outside these camera limits it reports an explicit preview error.
