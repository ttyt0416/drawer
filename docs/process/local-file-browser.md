# 248 — Common local file browser and physical-operation policies

Primary Open/new image/new image-layer routes and local-files use one browser. Folder scans and thumbnail reads use one owned worker, generation checks and cancellation. Changing address clears old rows/selection/tickets immediately. Preferences persist view, sorting, filters, last successful folder and up to64 canonical favorites. Missing favorites are retained, not probed at startup. Corrupt settings need explicit replacement; atomic saves preserve previous data and foreign temporary files.

The OS boundary checks drive type before traversal and excludes mapped network drives. Core inspects every component for reparse points before canonicalizing. URLs, UNC, parent traversal and non-Unicode paths are refused. Listings are limited to8192 matches/16MiB metadata; sort keys are name/extension/mtime/extension+mtime with deterministic ties and folders first. Details show UTC dates. Fixed-height visible rows keep rendering bounded.

Thumbnails validate signatures/source metadata, open native/still/PSD within reserved memory and sample a96px sRGB composite. Contents/ICC/alpha/DPI are never edited. Unsupported/large/corrupt files retain reasons. All refresh streams through a capacity2 queue and at most128 cached images; scrolling regenerates missing visible items. No source/output artwork is deleted by cache refresh.

Physical tickets capture checked source metadata and exact new path or recycle target. Confirm revalidates. New folders use exclusive create; native rename is a no-replace move. UTF-16 length, reserved/device names and collisions are checked. Read-only files and recycle trees with reparse points are refused. The controller remaps open native/source paths, imported-source protection, favorites/recent paths, preserving drawing history. Recycled open native files remain in memory as unsaved targets. Native Save is blocked during physical operations. Application data folders use their dedicated management workflow. Outcomes reconcile even if the browser closes; preference-write failure is reported separately from a completed physical operation.

Windows Shell IFileOperation runs in an owned STA with recycle-only/undo/early-failure flags. PreDeleteItem vetoes transfers without recycling and vetoes cancellation; no permanent-delete fallback exists. HRESULT/aborted callbacks and source disappearance determine outcomes. Verification directly tests the veto and sends an exclusive temporary fixture through the actual Shell callback in forced-veto mode: no deletion is performed. If Shell is unavailable before that callback, the fixture must still be intact. App pointer tests use an exclusive same-volume simulated bin to test confirmation and open-document state; real user confirmation uses the native adapter.

Checks cover Unicode, paths exceeding260 characters, missing folders, source bytes, thumbnails/error, view/favorite restart, filtering/sort direction, collisions/read-only, foreign settings temp files, native rename, recent/open path changes, keyboard open, canceled review and open memory/history after confirmed simulated recycle. Feature253 extends detailed explorer integration using this common policy.

Primary API references: [IFileOperation flags](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags), [PreDeleteItem cancellation](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperationprogresssink-predeleteitem). Existing windows-core0.62.2 is directly referenced for its COM macro; library versions/count are unchanged.

Native checks additionally compared normal and extended Windows path spellings. Shell receives its supported path spelling and the bound filesystem path must match before any operation. The restricted tool process reported transfer flags514 and was vetoed; the normal-permission forced-veto probe reported642, including the documented recycle bit. Every probe kept its exclusive fixture unchanged. The recycle predicate was not relaxed to accept the restricted permanent-delete path.

Multiple-file Open is retained through bounded Ctrl/Shift selection and a serialized queue; existing image import review is completed before the next selected file is opened. Physical rename/recycle review uses one selected target.
