# 안정성·실패 처리 검증 (303)

`scripts/test-checklist.ps1 -Item 303 -TimeoutSeconds 900`은 실제 배포본의 CPU 문서 작업을 최소600초 연속 실행한다. 편집/Undo/Redo를 반복하고256회마다 저장·재열기하고 실제 편집기 CPU 프레임을 갱신한다. 화면 표시는 측정하지 않는다. 이력은8단계/1MiB로 제한하며 각 작업은5초 이내여야 한다. 부모 프로세스가1초 간격으로 Windows private bytes/working set을 측정한다. 예열60~180초와480초 이후의 private bytes 평균 차이가64MiB를 넘으면 실패한다. 원시 표본·시간·문서 할당량·최대 작업 시간은 check-303-evidence.json에 보관한다. 이 유한 시험은 모든 장시간 사용이나 누수 부재의 증명이 아니다.

호스트 디스크나 RAM을 고갈시키지 않는다. 실제 저장 파이프라인의 공개 전7개 단계에 StorageFull 오류를 주입해 정상본·픽셀/메타데이터·수정표시·경로·이력 불변을 확인한다. 0가용공간 사전 검사, 문서 메모리 예산 고갈 및 복구도 별도로 검사한다. 잘린/무결성 손상/미지원 버전4개 입력은5초 이내 거부하고 입력·정상본을 바꾸지 않는다. 293의 실제 프로세스 종료/복구 검증과 함께 사용한다. 전원 차단·실제 시스템 OOM·실물 펜 세션을 대신하지 않는다.

빠른 단위 시험은768회로3번의 편집기 프레임 경계를 지난다. 앱 설정과 문서에 같은 이력 한도를 적용한다. 배포 증거로 인정할 때에는600초와 최소500개의 OS 메모리 표본을 강제하며 단위 시험 결과로 이 조건을 대체하지 않는다. 0길이 선·1×32768 이미지·1e-9 이동·최대256레이어 병합 경계도 실행한다.

실측: 600.0107초, 270124회 편집/Undo/Redo, 1055회 저장·재열기, 작업 최대45.3539ms. OS594표본의 전용 메모리 평균은 예열29.70MiB/후반29.67MiB였다. 집계 코드의 사전 속성 측정/경로 변수 충돌을 수정한 뒤 원시 표본과 원래 실행 영수증 SHA-256을 확인해 재집계했다. worker 재실행을 주장하지 않는다. 집계 정상2종/오류5종 및 실행기 자동 정리 회귀를 별도로 통과했다.
