# 245 — Resumable action execution and local batches

Action settings and parameter editing remain in the local auto-action editor. Runner snapshots are frozen so editing a sequence cannot silently change its already-executed prefix. A private document copy retains work-time, light-table, view/tool, camera/onion/keyframe metadata; each operation prepares an atomic DocumentState. Only a successful whole step advances the cursor. Cancelled/failed operations do not install partial state. Retry starts at that step; explicit skip or skip-error advances it once. Complete active-document results require Apply, validate original id/revision/frame, and create one Undo.

Batches process1..128 local inputs sequentially; memory is bounded against current workspace and each input opens within one twelfth of the available budget. Inputs are fingerprinted before/after reading and before publication. New native outputs are limited to64MiB, named using the common validated title/index rules, synced through an exclusive sibling temporary file and published with a hard link that cannot replace an existing target. Completed output cursor/result is committed in memory before log writing, including cancellation immediately after publication; subsequent resume cannot replay completed files. Log failure pauses before further files. Only owned temporary files are removed; an exceptional cleanup failure after publication is a success with its exact cleanup warning.

Logs are version1 local JSON, limited8MiB; at most16 notices plus an omitted count/file and512characters/notice. They record frozen action, current file/step and per-file outputs/errors. Atomic updates protect the previously written hash; foreign log changes are not overwritten. Stop/skip for operation errors is independent of stop/skip for failed files. Manual Skip file records the result before continuing. No input is saved or modified. Sources that change externally are refused, not reverted. Discard preserves completed new outputs and logs. Resume requires the still-live session; restart recovery and repetition/wait semantics are separate later features.

Validation covers stop/retry without duplicate layer creation, cancellation at a step boundary, explicit skip, one Undo/Redo, stale document refusal, broken second input, skipped files, original byte hashes, changed sources, output collisions, local JSON readback and foreign log protection. App replay clicks run, skip, resume, apply, file-batch and close, with private worker results. No physical pen or third-party app control is involved.
