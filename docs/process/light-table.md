# 201 — Light table and reference placement

`light-table` opens reference registration and placement controls. Common registrations appear for every cel; per-cel registrations use the stable editable cel-definition ID. Choose the cel list independently of the editing pin. A layer reference follows the original layer/cel, an onion reference evaluates an explicit frame and optional cel track, a local PNG/.drawer reference stores both its local path and a portable image copy, and another-canvas copy is a frozen snapshot with its source title. External files refresh explicitly; failed refresh preserves the saved copy and reports the missing source. Deleted layer/cel/frame references remain records with a missing-source notice, so drawing Undo can restore their targets. Network/URL/UNC origins are rejected.

Reference position, positive independent x/y scale, rotation, pivot, individual opacity, tint mode/color, name and common/per-cel scope are document auxiliary objects. Overall opacity multiplies individual opacity; zero does not overwrite individual values. Original/Half/Solid tint uses the same independent sRGB definition as200. References are composed in registration order above the drawing with default30% overall opacity. This overlay is separate from onion display and is never sent to the drawing renderer or export.

The placement view supports Move/Rotate drags and a Pivot click tool. Drag release commits one reference edit; Escape resets the draft. Pivot clicks change the stored local pivot/offset while preserving the complete current matrix. Numeric/color/name/scope changes remain a preview until Apply. Saving or closing while a placement draft is pending asks the user to Apply or reset first; closing the reference panel resets its draft. Center on reference / canvas centers the selected pivot, or the canvas when no reference is selected, and changes viewing position only. Move/Rotate/Pivot defaults persist through the existing local workspace preference/backup system.

Pin editing cel opens the existing separate editable cel-content canvas, preserving its definition ID across frame/reference changes. Reference selection/manipulation never selects a drawing layer. The parent canvas is blocked while a cel is pinned; painting is allowed only in its fixed content tab. Removing, hiding or locking the cel blocks drawing until the target is restored or the pin is explicitly released. Switching to an unrelated document retains each document's pin independently. Apply cel content retains the existing parent revision/source checks; after other parent edits, reopen the cel before applying. Apply content and Return explicitly release the editing pin; the independent content document remains open. A blocked canvas always provides release/open-controls buttons even when the panel is closed. Pin/release and center/view display are session choices, excluded from document data, dirty state and drawing Undo.

Each reference edit has its own Undo/Redo, separate from pixel/object history. Auxiliary history has its own saved marker; dirty is the union of drawing and reference changes. Undoing back to the auxiliary save point restores its clean status while preserving drawing edits. Closing a drawing with only a reference edit requests saving. Saving includes the current auxiliary data and marks both histories saved. Reopening restores objects/images with empty histories and no pin/display state. Drawing Undo preserves reference objects.

Native100 stores reference metadata in a checked JSON transport field that is unpacked outside Scene/drawing snapshots. RGBA8 sRGB reference images use an out-of-line payload after timing data, with dimensions/length and SHA256 verification. Image metadata is deduplicated within the document. Legacy8-bit documents force the precision delimiter before a reference image payload, even with no page/cel tables. Metadata-only auxiliary documents can retain the normal legacy footer policy. Old headers, truncation, image damage, invalid scopes/poses and save destinations equal to reference files are rejected. Reference file records may be missing and still retain their cached pixels.

Limits:128 registrations,32 distinct images,64MiB of reference objects/history,64 recent edits (older entries may be pruned while preserving the latest Undo),16 onion-frame snapshots and16Mi source samples per preview, side<=1024. Native JSON retains the existing4MiB metadata limit; normal document/resident budgets also apply. File formats verified here are local PNG and .drawer. Image copies are guides at RGBA8; high precision original drawing data remains intact.

Core verification checks common/per-cel isolation, live source edits, cached file refresh/missing status, copy/onion sources, pivot-preserving matrices/rotation, multiply/zero alpha, independent history/dirty/save/reopen, source deletion and locked pins, old/corrupt headers, footer boundaries, untrusted image bounds and actual PNG guide exclusion. App verification uses pointer events for registration, pivot, movement and rotation, tests close/save prompting, view history isolation, the fixed content target, frame changes/deletion/Undo, another-document switching, center-view isolation, Escape/release cancellation and workspace reload. Installed smoke includes `light_table=true`.
