# 전체 로컬 백업·복원

Local data maintenance에서 먼저 모든 그림/프로젝트 변경을 저장한다.
Select saved document files로 추가할 저장 파일을 고르고 Create full local backup에서
존재하지 않는 새 폴더 이름을 지정한다. 설정·프리셋·소재·색인·로컬 작업 기록을
포함한 사용자 저장소 전체와 명시적으로 선택한 문서 파일을 묶는다.
외부 참조/프로젝트의 별도 동반 파일은 자동 추적하지 않으므로 함께 선택한다.
같은 이름의 문서 파일은 이름을 구분한 뒤 다시 선택한다. 원본 파일은 바꾸지 않는다.

묶음은 bundle.json 버전1, 앱 버전, Native125, 원래 데이터 위치와 상대 파일별
길이/SHA256, userdata/, documents/로 구성된다. 최대16GiB·32768항목·깊이32·
문서1024개다. 스냅샷 전후 목록/해시가 일치해야 게시한다. 남은 공간은 목적지
볼륨에서 측정한다. URL/네트워크 위치·부모 탈출·링크·중복·기존 목적지를 거절한다.

Choose full local backup folder 후 확인을 켜고 Restore full backup에서 새 폴더를
선택한다. 전체 버전/파일 목록/길이/해시와 공간을 먼저 검사한다. 현재 사용자
저장소는 `<새 폴더>-before-restore`에 독립 백업하고 기존 위치도 보존한다.
별도의 전용 임시 폴더에 복사/검증하여 새 복원 위치로 게시한 다음 bootstrap의
로컬 위치 기록 하나만 원자적으로 바꾼다. 설정/소재/색인의 관리 경로는 새 위치로
바꾼다. 추가 문서는 새 위치의 restored-documents에만 복사하며 원래 파일을
덮지 않는다. 그 폴더와 이미 존재하는 자료가 충돌하면 복원을 거절한다.

성공하면 편집을 멈추고 닫기/재시작을 안내한다. 재시작이 복원된 설정을 읽는다.
실패/취소/공간 부족/손상은 활성 위치 기록을 바꾸지 않는다. 마지막 위치 기록
쓰기만 실패했다면 검증된 새 복사본과 현재 자료 백업은 보존한다. 실패한 전용
임시 폴더는 소유 기록과 링크 없는 목록이 확인되는 경우에만 정리한다.
사용자가 바꾼/알 수 없는 자료는 자동 삭제하지 않는다. 디스크0은 결정적 주입
시험으로 검증하며 실제 디스크를 가득 채우지 않는다.
