# 203 — 로컬 오디오·샘플 동기 재생·스크러빙·WAV 출력

`timeline-audio` 명령은 Import, Clips / volume, WAV output 탭을 제공한다. 타임라인을 만든 문서에서 사용하며 셀 내용 탭에서는 부모 타임라인에 연결한다. 원격 음원을 가져오는 기능은 없다.

## 입력과 저장

- RIFF WAV의 PCM8/16/24/32, IEEE float32, 해당 WAVE_FORMAT_EXTENSIBLE 형식을 지원한다. 입력은8..192kHz의 모노/스테레오다. 압축 WAV, RF64, RIFX, 다른 코덱은 명시 거절한다.
- 헤더 없는 파일은 사용자가 PCM16LE와 샘플률/채널 수를 직접 선택한다. 헤더를 추측하지 않는다. 입력64MiB, 디코딩 결과32M개 인터리브 샘플, 오디오32클립, 타임라인10000프레임 한도를 적용한다. 원본 길이 때문에 한도를 넘으면 외부에서 잘라 다시 가져오도록 거절한다.
- 원본은 디코딩된16비트 PCM으로 저장한다. 24/32비트와 float의 정밀도 감소·float 범위 잘림은 삽입 전 명시 확인한다. 원래 WAV 컨테이너의 메타데이터/고정밀 원문 바이트를 보존한다고 주장하지 않는다. 파일은 수정하지 않는다.
- 포함 모드는 독립 PCM과 원래 파일의 경로/해시 출처를 기록한다. 링크 모드는 같은 PCM 캐시와 경로·전체 파일 SHA256·raw 해석값을 저장한다. 재생은 항상 저장된 PCM을 사용한다. 누락/변경된 링크를 검사해 안내하고 자동 갱신하지 않는다. URL/UNC 및 링크 파일 입력을 거절한다.
- Refresh는 같은 원본을 공유하는 모든 클립을 확인 후 갱신한다. 샘플률/채널은 유지하고 기존 트림/침묵 구간과 믹싱 값을 보존한다. 짧아진 원본이 기존 구간을 충족하지 않거나 공유 클립이 잠겼으면 전체 갱신을 거절한다.

native102는 기존97의 AudioClip에 선택적 sound(gain0..400%, mute, source)를 추가한다. 생략은100%/재생/내장 원본이다. 실제 PCM/원본 해시 페이로드는97의 형식을 유지한다. 새 설정이 들어 있는101 이하 헤더는 거절한다. 음원 누락이 문서 열기나 저장된 PCM을 훼손하지 않는다. 클립 이름·시작 위치·볼륨·뮤트·삽입·제거·갱신은 한 문서 Undo/Redo로 복원하며 재생·스크러빙·출력은 그림 이력/dirty를 바꾸지 않는다. FPS 변환과 시간 삽입/분할은 sound 출처와 값을 상속한다.

## 재생과 시간

Windows 기본 출력 장치에48kHz/스테레오 PCM16을 작은 버퍼4개로 공급한다. 한 버퍼는1024 샘플 프레임이며 기본 큐는 약85ms다. 헤더와 PCM은 전용 스레드의 안정된 할당에 보존하고 unprepare 성공 또는 reset으로 반환된 뒤에만 수정/해제한다. 종료·문서 전환·편집은 재생을 중지한다. 장치/형식 오류는 안내하고 기존 화면 재생과 WAV 출력을 유지한다.

화면은 장치가 소비한 샘플 수를 기준으로 프레임을 선택한다. 바이트/밀리초 위치를 반환하는 장치도 환산하고32비트 카운터 래핑을 확장한다. 프레임 경계는 유리수 FPS와 u128 정수의 half-up 표본 경계다. 프레임마다 반올림 시간을 누적하지 않는다. 범위 중간에서 시작하고 범위 처음으로 반복하는 경우도 같은 경계를 사용한다.

PCM은 샘플 단위 위치를 유리수로 계산해 선형 보간하고 볼륨/뮤트를 적용한 뒤 합산한다. 모노는 양쪽에 복제하고 스테레오는 유지한다. 기존 다채널 PCM은 채널 배치 정보가 없으므로 전체 채널 평균을 모노로 사용한다. 출력의 범위 초과 샘플은 포화 처리하고 개수를 표시해 볼륨 감소를 안내한다.

Scrub은 현재 프레임부터 최대4800 샘플 프레임(100ms)을 재생한다. 종료 제한은 오디오 스트림 자체에 있으므로 화면 갱신이 지연되어도 더 오래 공급하지 않는다. 프레임 변경 스크럽과 숫자 탐색을 제공하며 그림/현재 프레임을 소리 때문에 임의로 전환하지 않는다. 재생 중 표시하는 최대 관측 지연은 장치 위치를 반영하기 직전의 화면 프레임 지연이다. 스피커·모니터의 물리 지연은 측정하지 않는다.

## WAV 출력

첫/끝 포함 범위,8..192kHz, 모노/스테레오 PCM16으로 내보낸다. 출력 시 PCM/값/원본 출처를 고정하고 이후의 편집·갱신을 섞지 않는다.4096샘플 프레임 단위로 생성하여 전체 믹스를 메모리에 쌓지 않는다. RIFF4GiB를 넘으면 범위 축소를 요구한다. 현재 문서/입력 원본 경로에는 출력하지 않는다. 기존 파일은 교체 확인을 요구하고 작업 시작/게시 직전 해시로 변경을 검사한다. 개인 임시 파일에 쓰고 동기화한 뒤 마지막에 게시하며 취소/실패는 그 작업의 미완성 파일만 정리한다. 정상 게시된 WAV를 문서 Undo로 삭제하지 않는다.

미확정 클립 값과 준비된 입력은 적용/초기화·삽입/폐기 전 저장/닫기에서 빠지지 않도록 차단한다. 별도 WAV 출력 작업은 원문서 저장과 독립이다. 앱의 입력/출력 파일 처리는 취소 가능한 작업으로 실행한다.

## 검증

독립 WAV 바이트로8/16/24/32비트·float·확장 헤더·raw 정렬·NaN/손상/미지원 코덱을 검사한다. 위치·게인·뮤트·실제 출력 샘플·한 Undo·native102/구버전 위장·파일 누락/갱신·공유 원본·잠금·분할/리타임·정확한30000/1001FPS 프레임 경계10000개/반복10000회·100ms 제한을 검사한다. 실제 WAV 디코딩/재출력 바이트 일치·스냅샷 편집 격리·파일 충돌/원본 보존·중도 취소와 임시 파일 정리를 포함한다. 앱은 실제 포인터 준비/삽입/볼륨/재생/스크러빙/출력과 장치 없음·지연된 화면 갱신·오래된 입력·문서 전환을 재현한다. Windows 어댑터 검증은 실제 장치에250ms의 무음12000샘플 프레임을 공급하고 완료/카운터와 단조시계 차이를 기록한다. 장치가 없으면 그 상태를 별도로 보고하며 음향 품질이나 물리 시청각 지연의 검증으로 표시하지 않는다.

API 근거: [Microsoft WAVEFORMATEX](https://learn.microsoft.com/en-us/windows/win32/api/mmreg/ns-mmreg-waveformatex), [Microsoft waveform functions](https://learn.microsoft.com/en-us/windows/win32/multimedia/waveform-functions). 입력 컨테이너 규격은 [McGill WAVE specification](https://www.mmsp.ece.mcgill.ca/Documents/AudioFormats/WAVE/WAVE.html)을 따른 독립 구현이다.
