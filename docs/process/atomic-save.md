# Verified atomic saves

Native documents and project manifests share a verified publication primitive. An exclusive temporary is written, flushed, synchronized, closed and reopened through the actual format validator. A regular, healthy existing destination is copied to a synchronized, validated predecessor and published as `<original>.drawer-last-good` before the new destination is replaced. Generation references in old project manifests remain protected because prior page directories are retained.

Errors before replacement preserve the original document, dirty state and history. The predecessor remains available after a successful save. An unreadable/unknown existing destination selected for replacement is preserved byte-for-byte in a synchronized hash-named `.drawer-unverified-<sha256>` file first. This is not treated as healthy and never displaces the last healthy predecessor. Native Save reports that retained path. A collision or preservation error refuses the replacement. Existing foreign temporaries are never removed. Restart opens only the named destination, never an incomplete temporary. An error in a completion observer after publication cannot reverse an already completed save.

Streaming size/hash stamps detect a destination changed during preparation or just before replacement. OS sharing violations are reported without a copy/delete fallback. This is not a filesystem transaction against arbitrary external writers between the final check and rename; keep a document under one editor's ownership. Physical power loss is not claimed as measured. The fault test models termination points, retained partial bytes, write/flush/sync/verification/predecessor/replace interruptions and an actual Windows share-denied destination. Reopen accepts a complete old/new destination only; the last healthy predecessor is retained.
