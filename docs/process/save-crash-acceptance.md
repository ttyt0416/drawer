# Item 293: save failures and actual process termination

Run `scripts/test-checklist.ps1 -Item 293`. The existing atomic-writer error injection, recovery-generation validation and production startup recovery dialog tests run first. The new matrix then launches eight owned hidden child processes, one for each save stage: Created, Written, Flushed, Synced, Verified, BackupReady, Replacing and Published.

Each child opens an owned healthy document, makes a known edit and checkpoints that edited document plus a second unsaved document into a live recovery session. Inside the real `files::save_observed` callback it atomically publishes a stage/PID marker and parks while holding the live session. The parent observes the exact marker, kills and reaps the child, then restarts the scanner. A 30-second deadline and an owned-child destructor kill/reap on failure; the marker is rename-published to avoid observing a partial ready record.

Before publication the normal document must equal the exact healthy original bytes. At Published it must be the complete new generation with the known edited pixel and a valid Native reader/integrity footer. The normal directory has exactly one `.drawer` document; writer intermediates are never counted as normal documents. Startup recovery finds exactly two complete documents, keeps saved/unsaved identities separate and restores their expected edits. Recovered copies are dirty and have no write-back path. The UI tests exercise recovery guidance, confirmation, discard and original-file preservation.

The unit test also starts and kills real processes using an exact child-test entry point. The packaged acceptance uses a private CLI worker before creating a window. Workers accept only a local admitted directory and a hash-bound bounded configuration. All source files, diagnostics, partial saves and recovery snapshots are owned fixtures removed after the parent has reaped children. This verifies forced process termination and injected I/O errors; physical machine power loss is separate evidence.

The startup-dialog fixture initializes recovery explicitly only when production auto-startup did not already initialize it. Unit tests and smoke mode skip auto-startup; ordinary packaged verification does not. This prevents the fixture itself from opening a second session and misclassifying its first empty session as unresolved.
