# 타임라인 시간 편집

기능198은 timeline-timing 명령에서 FPS, 재생 범위/반복, 셀 배치 규칙, 프레임 삽입/삭제를 검토한 뒤 확정한다. 표의 충돌·최소길이·삭제 확인이 하나라도 없으면 Core Prepared.commit도 거절한다. 준비는 취소 가능한 작업이며 문서 ID/수정 번호가 달라지면 다시 준비해야 한다. 한 확정은 하나의 문서 Undo/Redo다. 위치만 옮기는 재생헤드는 표를 무효화하지 않는다.

FPS 실제 시간 유지의 경계는 oldFrame×newNumerator×oldDenominator/(newDenominator×oldNumerator)를 u128 정수로 계산하고 half-up 반올림한다. 프레임 위치 유지는 인덱스를 유지한다. 노출이0길이가 되거나 앞 노출과 겹치면 각 노출마다 최소1프레임·뒤 경계 이동을 확인한다. 출력 프레임 키가 합쳐지면 남길 원래 키를 직접 고른다. 셀 클립도 노출 경계 보정과 함께 변환하고 필요한 최소 길이는 별도 확인한다. 전체 길이는 필요한 경계를 담도록 늘어나며10000프레임을 넘으면 거절한다. 첫/끝 포함 UI는 내부 시작 포함/끝 제외로 바뀐다.

재생 범위/반복과 라벨 연동은 문서에 저장한다. 링크를 끈 라벨은 위치를 유지하며 짧아진 타임라인 밖에서도 휴면 상태로 보존한다. 휴면 라벨은 탐색에서 제외한다. 다시 연동할 때 필요한 범위 확장은 확인한다. 일반 셀 이동/그리기 이력은 재생 자체가 바꾸지 않는다.

셀 트랙은 안정 ID의 독립 클립 구간을 가진다. 분할 삽입은 경계 좌/우 클립과 빈 간격을 만들고 비분할은 기존 셀 유지 구간을 늘린다. 삭제 분할은 남은 좌/우 클립의 ID 관계를 보존/분리하며 비분할은 한 구간을 줄인다. 선택 트랙만 편집할 때 다른 소유자의 시간 데이터는 그대로다. 전역 키/라벨/재생 범위는 선택 트랙과 별도로 고르는 전역 소유자다. 모든 프레임을 삭제해도 문서는1프레임이고 셀 정의·원본 PCM은 명시 정리 전까지 남는다.

오디오는 원래 i16 PCM/샘플률/채널을 불변 원본으로 내장하고 클립마다 원본 ID·샘플 프레임 단위 범위 또는 침묵 구간을 저장한다. 기존 Timeline.audio는 실제 사용할 캐시 PCM이고 원본을 대체하지 않는다. FPS 경계 변경은 파형을 리샘플링하지 않고 범위 밖을 자르고 다시 늘릴 때 보존된 원본 꼬리를 복구하며 원본을 넘는 부분만 침묵으로 채운다. 삽입/삭제는 원본 부분과 침묵 구간을 나누거나 이어 붙인다. 한 클립을 분리하면 원본은 공유하고 클립 ID는 독립이다. 잠긴 오디오/셀/트랙이 영향 범위에 있으면 전체 거절한다. 음원 재생/믹싱 도구 완료를 주장하는 항목은 아니며 실제 PCM 연결의 타이밍/파형 보존을 검증한다.

배치 규칙은 ID 구간/자연순 이름 구간, step, 셀당 길이, 빈 간격, 반복횟수 또는 끝까지 반복이다. 이름 양끝이 중복이면 ID를 요구하며 숫자 ID의 누락은 건너뛴다. 표에는 실제 배치 구간을 표시한다. 한 프레임 범위와 마지막 잘림을 허용하고 영역 밖은 유지한다. 빈 간격은 투명 셀 슬롯으로 저장하며 나중에 일반 셀처럼 편집 가능하다. 규칙64개를 로컬 작업공간에 저장하며 그림 이력과 분리한다.

네이티브97은 Scene.timing의 재생 범위·라벨 연동·클립·오디오 원본/범위 메타데이터를 저장하고 셀 원본 테이블 뒤에 원본 PCM을 little-endian으로 기록한다. 샘플 수/채널/예산과 원본 전체 SHA256을 검증한다. 구버전 위장 헤더와 사용하지 않는 원본의 손상도 거절한다. 클립2048개, 활성 오디오32개, 원본128개, 클립당4096샘플 구간과 기존32Mi샘플·문서/Undo 메모리 한도를 적용한다. 원본 PCM을 씬 JSON의4MiB 한도로 잘못 계산하지 않도록 바이너리 페이로드를 제외한다. 기존 문서는 기본 설정으로 읽으며 타이밍 원본이 있으면8비트 문서도 정밀도 footer를 기록한다. 출력/래스터화의 명시적 전체 소스 초기화는 해당 시간 메타데이터도 제거한다.
