# 빌드 캐시 정리

`scripts/cleanup.ps1 -KeepBuild latest`는 `target/latest`라는 폴더 이름만 보존하는 작업이 아니다. 검증된 최신 릴리스의 Cargo 산출물 목록을 조회해 그 빌드에 실제로 필요한 캐시만 남긴다.

- 최신 release 실행 파일·PDB와 의존성 rlib/rmeta/DLL/PDB·dep-info, 빌드 스크립트/출력·fingerprint를 보존한다. 같은 이름이어도 현재 빌드에 필요한 서로 다른 버전/해시는 모두 유지한다.
- Cargo가 공개 실행 파일 목록에 생략하는 `deps/drawer_app.exe`, PDB, dep-info도 유지한다. 이 사본을 지우면 나머지 의존성이 있어도 앱을 다시 컴파일하게 된다.
- 이전 debug 프로필 전체와 증분 캐시, 현재 릴리스에 사용하지 않는 해시/빌드 스크립트/기록, 다른 item-* 캐시를 제거한다. 최신 릴리스도 재생성 가능한 증분 데이터는 보관하지 않는다.
- 완성된 Cargo 빌드 목록과 앱 실행 파일이 없으면 삭제하지 않는다. 절대 경로가 캐시 루트 안에 있는지 확인하고 중첩된 junction/symlink도 삭제 전에 거절한다. 소스·배포 ZIP·Git 기록은 정리 대상이 아니다.
- 삭제 전후 실행 파일 체크섬을 확인하고 동일한 릴리스 명령을 다시 실행해 모든 항목이 fresh이고 재컴파일이0개인지 검사한다. 마지막 목록은 캐시 안의 active-release-artifacts.jsonl에 기록한다.
- 정리 전후 파일 크기 합계를 출력한다. 하드링크 중복 때문에 실제 디스크 점유/회수 용량과 차이가 있을 수 있다. 다음 디버그 테스트 빌드는 debug 캐시를 새로 만들므로 시간이 더 걸릴 수 있다.

검증: `scripts/test-cleanup.ps1`은 별도 개인 폴더에서 최신/구형/동명 복수 버전·네이티브 빌드 출력·실행 파일 내부 사본을 구성해 필요한 파일 보존과 구형/증분 제거를 확인한다. 빌드 실패·캐시 밖 경로·중첩 링크 입력이 실제 삭제 전에 거절되고 외부 파일이 유지되는지 검사한다. 검증 폴더도 확인된 작업 범위 안에서만 정리한다.
