# Raster page interchange contract

`page-exchange` imports selected static PDF pages through Windows.Data.Pdf on a dedicated MTA worker, from the exact byte snapshot validated by lopdf. Empty-password encryption is also rejected using retained decryption state. Every parsed dictionary (including compressed object dictionaries) is checked for script actions, remote references, attachments and external streams. Source bytes are never changed. DPI1..4800,32MiB PDF input,512 pages,32768 dimensions and a128MiB composition budget bound normal operations. Windows rendering is used as an independent reader of our PDF output in automated checks.

PDF output stores one RGB image plus soft alpha mask per page, a physical MediaBox derived from DPI, and classic cross-reference tables compatible with the PDF1.4 header. Open live page snapshots and lazily opened closed project pages use the existing export renderer. View rotation/mirroring, proof views and viewport overlays stay outside export; explicit guide/number flags are retained. Original document associations, history, save markers and files remain unchanged.

The EPUB adapter supports a local fixed-layout image profile: first stored mimetype, one package, explicit pre-paginated metadata, navigation, and one full-page PNG/JPEG per XHTML with a matching viewport. PNG alpha and source DPI (via optional page meta) round-trip; absent DPI defaults to96. ICC conversion uses the existing RGB/Gray import boundary. No browser is invoked. ZIP members stay in memory with entry/expansion/XML/image limits; no archive member is extracted. DRM/encryption files, scripts, remote or escaping paths, unlisted/duplicate resources, DTD/entity resolution, unsupported media/CSS/layout and contradictory reflow overrides fail before documents are added. Selected pages are fully prepared and validated before all new document tabs are added. A late invalid page leaves the existing documents and history unchanged. Imported pages have independent mutable pixels and use the existing native save path.

Exports stage a newly-created regular file in the chosen local directory, sync it, check cancellation and publish through the platform no-replace boundary. Destination races preserve foreign bytes. Guards own only successfully created temporaries; failures/cancellation remove those temporaries. Existing files require a different output name. Native path publication also rejects embedded null characters.

Printing first prepares the selected composites; a user-invoked Windows dialog chooses device, paper and copies. The GDI adapter composites alpha onto white, uses top-down BGRA, preserves aspect ratio and centers each page within the printable extent. DC/global allocations are released on success, cancellation and failure. A failed page/end aborts only the owned print job. Automated mock-sink tests verify count/order, cancellation and abort; no physical paper job is sent during tests. Physical printer quality remains unverified.

Verification includes strict range boundaries, selected multi-page PDF and exact EPUB alpha/DPI round-trips, Windows PDF rasterization at96/192DPI, empty/real-password rejection, active/remote content, corrupt second page, allocation/cancel, publication races/cleanup, actual pointer confirmation, original document/history/source preservation and native reopen.

References: [EPUB3.3](https://www.w3.org/TR/epub-33/), [Windows PdfDocument](https://learn.microsoft.com/en-us/uwp/api/windows.data.pdf.pdfdocument), and the locally installed Windows0.62.2 SDK bindings for PDF, print dialogs and GDI. The adapter implements the profile above; it does not claim editable proprietary-format round-trip compatibility.
