# 300. Pointer/Wintab·다중 모니터·혼합 DPI

상태: **실물 시험 대기**. 사용자의 펜 실물 검증 보류 지시를 유지한다. 이 문서와 빈 JSON 양식은 실행 결과가 아니며 완료 근거로 사용하지 않는다.

현재 배포 실행 파일의 해시와 Native 형식은 양식의 referenceBuild에 기록했다. 실제 시험 시 사용한 빌드·장치·드라이버·OS·모니터·도구 설정을 다시 확인해 기록한다. 물리 픽셀·논리 좌표·문서 픽셀과 원시 입력·앱 계산·화면 표시의 측정값을 구분한다.

원본을 유지하는 새 로컬 시험 문서와 별도 저장 경로를 사용하고, 데이터 수집 방법과 관측 가능한 항목부터 정한다. 수집하지 못한 값은 미측정으로 남긴다. 단위 시험이나 합성 이벤트의 수치를 실물 값으로 옮겨 적지 않는다.

1. **backends** — 요청/실제 활성 백엔드와 실패 시 대체 사유를 각각 기록하고 동시에 한 펜 백엔드만 동작하는지 확인한다.
2. **mixed-dpi** — 각 모니터의 실제 해상도·OS 배율·물리/논리 좌표를 기록하고 창을 옮긴 뒤 알려진 문서 점의 실제 입력 위치를 비교한다.
3. **negative-desktop** — 음수 가상 데스크톱 좌표가 있는 배치의 모서리·가장자리·중앙을 시험한다.
4. **tablet-target** — 태블릿 입력 영역과 대상 모니터/캔버스 매핑을 바꾸고 가장자리·영역 밖·상대 좌표 설정을 확인한다.
5. **rotation-primary** — 화면 회전과 기본 모니터 변경 후 좌표·필압·새 접촉·이전 대상 제거 안내를 확인한다.
6. **pressure-and-duplicates** — 양 백엔드에서 필압 범위·곡선과 실제 마우스/호환 마우스 중복 여부를 별도로 비교한다.

288번은 앱 내부의 합성 좌표→문서 첫점 검증이다. OS 실제 커서와 드라이버 좌표, 모니터 이동·회전의 정확도까지 합격한 것으로 간주하지 않는다. 물리 픽셀/논리 포인트/문서 픽셀을 혼합하지 않고 기대점과 실제점의 단위·변환·오차를 함께 남긴다.

기록 양식: [physical-300-template.json](physical-300-template.json). 모든 사례는 not_run이고 수치·장치명·시각·결과는 비워 두었다.

완료 판정은 실제 시행 자료를 연결한 뒤 한다. 각 사례의 관측값·기대값·오차/실패와 해당 빌드·환경을 남기고, 미지원 속성은 지원 여부와 안내를 명시한다. 저장 전후 문서와 필요한 영상/이벤트 기록의 로컬 경로·해시를 보존한다. 필수 사례의 실제 결과가 없으면 체크리스트를 체크하지 않는다.
