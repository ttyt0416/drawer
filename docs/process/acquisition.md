# Local scanner and camera acquisition (049)

The application performs no device query or capture at ordinary startup. The user opens Scanner / camera, explicitly refreshes Windows local WIA 2.0 scanners/still cameras and video camera information, chooses a device and requests one image. WIA queries use WIA_DEVINFO_ENUM_LOCAL. Each provider can report an independent failure without hiding devices from the other provider. Device IDs and names are bounded; at most 64 devices are listed. No driver, cloud connector or runtime helper is downloaded or distributed.

WIA acquisition uses IWiaDevMgr2::GetImageDlg, with the selected ID, a newly created owned scratch directory and single-image/common-UI flags. It includes transfer to file, unlike DeviceDlg's image-selection-only contract. The raw HRESULT is retained: S_FALSE can include partially scanned files and is always treated as cancellation. All BSTR entries and their CoTaskMem array, returned interface, properties and STA COM apartment are released even on partial failure. No image is accepted unless exactly one path is returned and its canonical direct parent is our scratch directory. Foreign paths, links, protocol files, empty output and encoded images over 64 MiB are rejected.

Video capture uses DeviceInformation VideoCapture enumeration and MediaCapture with the selected VideoDeviceId, Video-only streaming (no microphone), automatic photo/video stream selection and PNG output to a memory stream. First initialization runs on the helper's main STA and pumps its own messages while WinRT operations finish, including consent callbacks. MediaCapture is explicitly closed before WinRT uninitialization. Connection, unsupported-format, busy-device and Windows access errors are reported. A successful enumeration is not a photo-capture test.

Both providers run in the same Drawer executable's explicit --acquire-helper mode. A bounded JSON request/response in an exclusively created local scratch directory carries IDs and output paths; command arguments never contain device IDs or shell text. The host remains responsive, polls cancellation and output size, and enforces 30 s discovery / 300 s acquisition deadlines. The Windows job has a 512 MiB process commitment limit and KILL_ON_JOB_CLOSE: host termination closes only its helper job, never the WIA service or other applications. Normal cancellation kills/waits the owned child before scratch cleanup. The helper is not a second packaged executable.

ImageSource applies the existing 64 MiB encoded, dimension, profile/orientation and total document-memory limits before decoding. RGB24 BMP support covers common WIA output, alongside PNG/JPEG/TIFF. Acquisition selects one still image/page. Original bytes are retained from the exact immutable decoder snapshot, with no reread race or extra encoded copy. Only an owned decoded preview reaches the UI; no document changes until the user accepts it. New-document insertion copies independent pixels. Layer insertion uses the existing reversible placement preview and one history entry, with the retained preview/original included in the memory reservation. The user may save byte-identical original data to a new chosen path; existing files cannot be overwritten. Close/refresh/reacquire discards an unsaved original preview.

Tests use independently generated PNG/BMP images and bounded protocol fixtures. They cover no devices, failure/disconnection, UI cancellation, existing document/history/dirty preservation, foreign/oversized/malformed paths and records, BMP dimension rejection, source-byte preservation, original create-new saving, new document and one-entry layer Undo/Redo. Packaged smoke runs protocol-only probes, real helper timeout/cancellation/job-handle termination and confirms scratch cleanup, without enumerating or capturing hardware. A separate manual local enumeration on this computer found one video camera and no WIA device, with no provider errors. No physical scan/photo was taken; successful hardware transfer remains unverified.
