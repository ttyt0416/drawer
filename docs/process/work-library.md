# 로컬 작품 목록과 복구 (259)

Local files → Work library 또는 work-library 명령으로 연다. 사용자가 선택한 로컬 파일1..64개를 한 번에 등록하며 목록은 최대512개다. 파일은 원래 위치에 남고 문서 내용은 업로드하거나 이동하지 않는다. 로컬 드라이브/경로·재분석 지점을 검사하며 저장된 외장 경로를 프로그램 시작 때 자동 탐색하지 않는다.

제목·쉼표로 구분한 레이블·즐겨찾기는 오른쪽 정보에서 저장한다. 제목/경로/수정 시각과 오름/내림차순, 즐겨찾기만 보기와 경로 레이블을 선택한다. 목록은 제목이 표시되며 원래 경로·파일 크기·수정 시각·읽기전용 여부·미리보기 상태를 정보에서 확인한다. 저장된 썸네일은 캐시임을 표시한다. Refresh / rebuild index를 누르면 현재 파일을 명시적으로 다시 확인하고 최대64개의96px 썸네일을 저장한다. 복잡하거나 큰/미지원 파일, 손상·누락·접근 거부·분리 장치는 오류를 표시하고 등록 경로는 남긴다. 접근 거부를 자동 파일 삭제로 취급하지 않는다. 창을 닫아도 취소한 작업 결과를 수집한다.

Reconnect file은 사용자가 고른 기존 로컬 파일로 목록 경로만 바꾸며 ID·제목·레이블·즐겨찾기를 보존한다. 다른 앱이나 파일 탐색에서 이동된 파일을 추측해 찾지 않는다. 열린 그림 문서의 출처/픽셀/이력을 임의로 다시 연결하지 않는다. Open work는 기존 문서/이미지 검토 경로를 사용하므로 전용 미지원 형식을 일부 읽기로 성공시키지 않는다.

Remove list entry (keep file)는 파일을 보존한다. Review file → Recycle Bin은 대상의 정확한 경로와 크기를 표시한 뒤 Confirm OS Recycle Bin을 눌러야 한다. 대상 스탬프·드라이브·재분석 지점·읽기전용과 앱 저장소 보호를 다시 검사하며 실제 OS 휴지통만 사용한다. 영구 삭제 대체는 없다. 파일을 이미 휴지통에 보냈으면 취소가 되돌리지 않는다. 열린 자체 문서는 픽셀/Undo를 유지하고 Save as가 필요한 상태로 남긴다. 파일 이동 후 목록 저장이 실패하면 파일 이동 사실을 표시하고 목록 항목은 남겨 재확인할 수 있게 한다.

Undo/Redo library metadata는 그림 실행 취소와 분리한32개 복구 단계이며 재시작 뒤에도 유지한다. 취소 후 새 목록 편집은 다시 실행 분기를 폐기한다. OS 파일 삭제는 이 복구 이력으로 되돌리지 않는다. 목록 정보를 되살리면 파일은 누락 상태로 보일 수 있으며 실제 파일은 OS 휴지통에서 복원한다.

목록·이력은 로컬 버전형 DB(8MiB 한도), 썸네일/정보는 재생성 가능한 별도 로컬 색인(32MiB 한도)에 저장한다. 쓰기는 세션 잠금과 이전 바이트 해시를 검사하고 완전한 새 파일을 동기화한 뒤 교체한다. 협력하는 두 세션이나 변경된 디스크 목록을 덮어쓰지 않는다. 실패/취소/중단 전에 공개한 목록·색인은 그대로며 재시작은 마지막 완전한 파일을 사용한다. 소유한 정상 헤더의 미완성 쓰기만 다음 작업에서 정리하고 알 수 없는 임시 파일은 보존한다. 직전 정상 DB 사본을 남긴다. 손상/읽기전용은 자동 초기화하지 않으며 확인한 복구는 현재 DB 바이트를 별도 보존한 후 직전 정상 목록 또는 빈 목록을 선택한다. 앱 데이터 폴더 이동은 작업 배출을 기다린다. DB 안의 등록 경로는 소재가 아닌 사용자 문서 식별이므로 데이터 폴더 이동 후에도 원래 경로로 유지한다.

검증: 등록/정보/즐겨찾기/정렬·필터/재연결/목록 제거와 이력·새 분기·재시작, 원본 바이트, 색인 공개 직전 실패/취소·중단 쓰기/이전 색인 재사용, 접근 거부/외장 분리·누락·손상·읽기전용·경쟁 세션·변경 파일·확인한 DB 복구, 등록된 앱 폴더 안 사용자 문서 경로의 데이터 이동 보존을 검사한다. 실제 포인터로 정보·정렬·보기·썸네일 작업·목록 제거/Undo·삭제 대상 검토/취소/확인·숨긴 작업 배출·재시작/복구를 확인한다. 파일 삭제 검증은 전용 소유 fixture의 모의 휴지통을 사용하고 실제 Shell 휴지통의 영구 삭제 거절은 기존248 플랫폼 검사로 유지한다.
