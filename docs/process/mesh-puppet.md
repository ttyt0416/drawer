# Mesh and puppet — checklist155

Layers → Mesh and puppet deformation operates on one or more paintable raster layers, including linked raster transform members. Convert non-raster sources explicitly first. It uses the pixel/selection, precision, lock, memory, save-notice and atomic Undo behavior of checklist154. Masks, textures and rulers stay fixed. The source document is never modified until Apply.

A2–5 column/row cage is split along each cell's top-left/bottom-right diagonal. Every destination triangle must retain positive area, and strict separating-axis tests reject overlapping interiors between any pair of triangles. This allows rigid90/180-degree rotations and concave outer cages without assuming that rows still run horizontally. Invalid/overlapping/folded cages remain visible in red; preparation clears any prior valid plan and refuses Apply.

Mesh grid mode edits a vertex by dragging it or entering normalized coordinates. Puppet mode starts from the rest grid and pins vertices. Choose a vertex and Add pin, or drag an unpinned vertex to add a movable pin. New pins retain the current pose at their vertex. Duplicate pins and vertex indexes outside the cage are rejected. Fixed pins retain their original position and zero rotation. Movable pins have a target position and screen-clockwise rotation. Pin targets may leave the original editing bounds, subject to coordinate/extent/fold limits; pin source anchors are always cage vertices.

Non-pinned vertices blend each pin's rigid transform with inverse squared document-pixel distance weights. Pinned vertices satisfy their target exactly. One pin gives a rigid translation/rotation of the entire cage; zero pins or pins with only identity transforms return the exact rest grid. With several pins, fixed anchors retain their positions and movable/rotated pins distribute motion through the intervening cage. Rotation is computed in document pixels, preserving aspect ratio for non-square editing bounds. Changing grid dimensions resets the cage and pins; switching modes retains the manual mesh and pin draft separately.

Inverse barycentric mapping samples the original8/16-bit layer with premultiplied bilinear interpolation. Selected pixels are cut/moved with their coverage, while the area selection follows the mesh. Sampling uses one immutable source per layer. Raster placements preserve off-canvas results; identity operations preserve storage and dirty/Undo/Redo. Nativev68 pixel/placement data is sufficient; cage/pins are temporary draft data.

Every destination triangle test and every4×4 selection sample contributes to the existing32M processing budget. This is deliberately bounded; reduce grid density, source size or selected extent when it is exceeded. Output is capped at4M pixels per layer and32768 per axis, with document/workspace/Undo limits checked before mutation. Save/Save As/direct app save require Apply or Cancel while the window remains open. Escape/window close discards the cage and pins.

Verification covers pins0/1/several, locked anchors, rigid90/180-degree rotation, exact pin targets and inverse mapping, duplicate/out-of-area pins, collapsed/folded and globally overlapping triangles, independent integer translation, selected boundaries and carried selection, native reopen and one Undo/Redo. CPU-only app replay covers actual mesh/pin dragging, automatic preview, mouse Apply, zero-pin dirty/Redo preservation, unconfirmed Save notice/no file, rotated-pin cancellation, rejected-fold invalidation and stale frames. Physical pen verification remains deferred.
