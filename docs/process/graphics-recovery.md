# GPU 오류와 로컬 소프트웨어 표시 (308)

Windows의 기본 표시 경로는 기존 OpenGL이다. 초기화 실패, 현재 WGL 컨텍스트 유실, OpenGL 오류 또는 사용자의 전환 요청을 감지하면 해당 창을 닫고 GPU를 사용하지 않는 winit/egui 입력·CPU 삼각형 렌더링·GDI 표시 창으로 전환한다. 문서 합성과 저장은 동일한 로컬 코어를 사용한다. `--software-rendering`으로 직접 시작하거나 F10의 Display recovery에서 전환할 수 있다. 그래픽 설정은 로컬 `settings/graphics.json`에 저장하며, 소프트웨어 표시 선택은 재시작 후에도 유지된다. GPU로 다시 시작하려면 이 설정을 해제하고 재시작한다.

새 UI 컨텍스트에 기존 문서 객체를 이동하므로 문서 데이터와 비공개 Undo/Redo 이력을 다시 직렬화해 재구성하지 않는다. 문서별 경로·수정 표시·이력 제한, 여러 보기와 선택한 보기·다음 보기 번호·보기 세션, 페이지 문서, 복구 세션, 참조·작업 시간·중지한 타임랩스 상태를 유지한다. 새 창의 그래픽 리소스를 다시 만든다. 미확정 입력·미리보기는 취소하며 백그라운드 저장을 정리하고 가능한 경우 전환 전에 로컬 복구 체크포인트를 남긴다. 원본 문서는 전환 때문에 덮어쓰지 않는다.

CPU 표시기는 egui의 잘린 삼각형·프리멀티플라이 알파·글꼴/이미지 텍스처와 순차 부분 갱신·샘플링/반복·상하 반전 없는 BGRA 출력을 처리한다. 공유 삼각형 가장자리를 한 번만 혼합하는 규칙을 시험한다. 화면 버퍼는 1,600만 픽셀, 프레임의 삼각형 경계 영역 연산은 1억2천만 회로 제한한다. 이 한도는 표시 자원에 대한 것으로 문서의 해상도·정밀도를 변경하지 않는다. 보조 창은 같은 소프트웨어 창 안에 표시한다. 현재 경로는 Windows 전용이며 다른 운영체제 지원을 의미하지 않는다.

`scripts/test-checklist.ps1 -Item 308 -TimeoutSeconds 900`은 자신이 만든 숨은 자식 프로세스와 문서만 사용한다. 원본 SAI/CSP나 사용자 문서를 열지 않는다.

- 초기화 실패를 주입하고 CPU 창에서 이어 그리기·Undo/Redo·저장/재열기를 확인한다.
- 자기 스레드의 WGL 컨텍스트를 실제로 해제하고 유실 감지·문서/이력 이동·CPU 창 편집을 확인한다. 다른 프로그램의 컨텍스트나 시스템 드라이버를 중단하지 않는다.
- GPU 메모리 부족 오류를 주입하고 같은 복구 경로를 확인한다. 실제 VRAM을 고갈시키지 않는다.
- 복구 설정을 복사한 별도 프로세스가 GPU 초기화 없이 소프트웨어 창으로 시작하고 편집·저장하는지 확인한다.

GPU가 있는 세 프로세스는 현재 장치의 실제 RGBA32F 셰이더 결과를 float64 CPU 기준과 비교하며, 양자화 후 채널 차이가 1을 넘으면 실패한다. 소프트웨어 표시와 GDI는 자기 메모리 DIB의 색 순서를 읽어 검증한다. 각 프로세스는 원본 파일의 SHA-256 불변, CPU 화면 해시, 문서 저장/재열기 일치, GPU 식별과 오류 종류를 기록한다. 재시작 프로세스에서는 새 GPU 검사를 했다고 표시하지 않는다. 호스트 조회는 [check-308-host.json](check-308-host.json)에 기록한 RTX5060Ti/Windows 드라이버32.0.16.1088이며, 실행 증거의 OpenGL 식별 문자열과 구분한다.

증거는 [check-308-evidence.json](check-308-evidence.json)에 보관한다. 오류 주입 시험은 실제 드라이버 재설치/중단, 물리적 장치 제거 또는 모든 GPU/드라이버 조합의 호환성 인증을 대신하지 않는다. 해당 하드웨어 시험이 남아 있으면 체크리스트 308을 완료로 표시하지 않는다. 실물 펜 시험과도 별개다.

2026-11-15 실행 결과: 네 자식 프로세스 모두 실제 CPU/GDI 창의 5프레임에서 기존 이력 1개를 보존하고 새 합성 마우스 획 1개를 Undo/Redo한 뒤 저장/재열기에 성공했다. 초기화·컨텍스트·메모리 사례는 위 GPU 기준 비교를 통과했고, 재시작 사례는 새 GPU 컨텍스트를 만들지 않았다. 최종 전체 자동 시험1083개, 경고 거부 검사와 배포본 설치/실행/재설치/제거·사용자 파일24개 보존을 통과했다. 시작 시 큰 상태의 스택 복사를 포인터 전달로 바꾸고 종료 이후 추가 프레임을 막은 수정도 이 배포본으로 확인했다. 숨은 창의 합성 입력 시험에서만 OS 입력 취소 콜백을 분리한다. 전체 하드웨어 기준은 `criterionComplete=false`로 남긴다.
