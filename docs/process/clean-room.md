# 구현 환경과 조사 자료의 분리

구현 작업 경계는 이 Git 저장소다. 상위 작업 폴더의 `work`는 조사 보관 영역이며 구현·빌드·전달 도구가 읽지 않는다. 원본 프로그램의 설치 경로도 빌드 입력으로 사용하지 않는다.

구현에 전달하는 자료는 `docs/specs/feature-checklist.md`의 사용자 동작과 독립 설계 명세 및 이 저장소에서 새로 작성한 파일이다. 전달 목록은 루트의 `handoff-files.txt`로 버전 관리한다.

`xtask prepare-handoff`는 목록 밖 파일을 복사하지 않는다. 절대 경로·상위 폴더 이동·숨김 경로·중복 경로·심볼릭 링크를 거절한다. 이 단계의 전달 파일은 UTF-8 텍스트이며 허용 확장자는 Rust 소스, Markdown, TOML, TXT, LOCK이다. 실행 파일·라이브러리·이미지·원본 리소스·디컴파일 결과는 전달 목록에 넣지 않는다.

묶음 생성 전 목록과 모든 입력 파일을 검증한다. 목록과 복사된 파일의 바이트가 같고, 추가 파일이 없는지 다시 확인한 다음 최신 묶음으로 교체한다. 실패 시 이전 정상 묶음을 보존하고 이번 임시 묶음을 삭제한다.

검사 도구는 파일 경계와 전달 목록을 검증한다. 새로 작성한 PowerShell 관리 스크립트도 소스 전달 형식으로 허용한다. `audit-specs`가 명세의 원본 코드·주소·자료구조 흔적을 검사하며 검토 결과는 `spec-review.md`에 보존한다.
