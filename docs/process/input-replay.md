# Virtual input replay

Virtual input replay runs the production Drawer UI/input pipeline in an independent CPU-only egui context with a new test document, no user storage and no native input/window connection. Existing user documents, history and clipboard are untouched. The worker preserves record time/order, converts document coordinates through the current test view and feeds normalized events through the same contact ownership, source filtering, pressure mapping, raster preview/commit and history code. Equal-time groups are split into batches of at most eight events to bound cancellation latency, without advancing recorded time.

Records contain version, 1–256px canvas dimensions and brush size, brush tip/shape/color/background, stabilization, pressure and device settings, simulated pen availability, expected stroke count, optional exact expected RGBA fingerprint, and samples with microsecond timestamps/source kind/device/contact/position/optional properties/origin. Limits: 4096 events, 512 distinct times, 100 starts, 24-hour virtual duration, 2 MiB JSON. Time must be nondecreasing. Wrong versions, invalid coordinates/pressure/settings, corrupt or oversized files are rejected before replay. No raw pointer, executable path or command is accepted.

The built-in record exercises zero, abrupt maximum, half pressure and release. Missing-end and reverse-time fixtures are selectable. Missing ends are cancelled by the production focus-loss path. Every successful run verifies Undo back to the initial document and Redo back to the resulting pixels. A PASS means the expected stroke count, optional supplied exact pixel fingerprint, and undo/redo assertions passed. The UI explicitly says when no expected pixel fingerprint was supplied. FNV-1a over stored RGBA bytes is a deterministic comparison fingerprint, not a security hash. Any history/resource limit that prevents complete restoration is a failure, not a partial pass.

The current brush settings can be copied into the record; changing the record cannot alter completed strokes or user documents. Records and reports are local JSON with explicit overwrite selection and atomic writes. Result reports include the input sequence and can be loaded back for another run; saved status is never trusted as a new result. Running work can be cancelled and closing the replay window requests cancellation. Worker errors retain no partial success label. Replay data and passing virtual cases never substitute for physical tablet/driver validation.

Known touch records can include attributes.palm and attributes.touch_frame. The latter is an explicit native-batch identity, not a timestamp guess. Keep a native two-finger batch at the same replay time to retain its complete-frame transformation. Finger drawing remains off unless pointer.touch.finger_drawing is explicitly enabled. Gesture-only replay changes no pixels or document undo entries. Physical touch validation is separate.
