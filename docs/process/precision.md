# Keyboard document editing — item 052

The Brush panel's Keyboard editing section selects Selection boundary, Selected pixels or Raster layer. The status displays that target and active Paint/Move/Eyedropper mode. Arrow presses move by one document pixel; Shift moves by ten, independent of view zoom, rotation, mirror or DPI. One held sequence shares a history group. Release, target/tool/command changes, focus or a modal ends the group. A new key press creates a new group; stale repeats cannot continue into a changed target. Focus transitions are conservatively suppressed in their receiving frame. Input fields, IME, menus and dialogs take priority. Explicit command assignments can override arrows through the existing shortcut path.

Each repeated move is calculated from a bounded original snapshot and total integer offset. Layer moves preserve their complete pixel extent outside the canvas. Selection boundary moves use a document-space translation after the page transform; they do not move page objects. Pixel moves split selected alpha from the original, clear that component, then composite the moved component over the cleared original. Feathered/overlapping moves never resample the preceding preview. The selection moves with its pixels. Empty/unavailable targets, locked layers, stale revisions, dimension/coordinate and memory limits fail before mutation. Repeated state edits merge only within the same live group and unsaved history checkpoint. A net-zero sequence removes its empty edit; unrelated edits, save, undo and redo cannot be merged into it.

Raster locks are visible in layer properties and block painting and pixel/layer movement; moving a selection boundary remains possible. Lock changes are ordinary undoable state commands. Native version 7 saves an explicit validated lock tag, reads versions 1–7 and defaults older rasters to unlocked. Selection translation is a defaulted geometry field and follows destructive page transforms as a vector. Selection sampling and navigator overlay use the same transformed/translated geometry.

L arms Connect last stroke to next click. Only a committed, nonempty stroke records an endpoint under its document/layer/tool key. The next accepted canvas Down creates a straight stroke with stabilization disabled from that endpoint to the clicked document point, then disarms. It uses the current brush/selection/lock/opacity pipeline and one pixel-history entry. Missing endpoints explain that a starting stroke is needed. Escape and tool changes cancel arming. Endpoints are bounded session data, removed when a document closes and excluded from saved files. They are independent between tools and layers; undoing pixels does not restore or serialize this session cursor.

Default shortcuts are [ / ] for size decrease/increase, Shift+[ / Shift+] for opacity steps of ten percentage points, 1–9 for 10–90% and 0 for 100%. Size steps are ten percent of the current value with a 0.1-pixel minimum, clamped to 0.1–4096. Brush opacity is stored per tool in local panel/workspace settings (older files default to one), multiplies the chosen color alpha and leaves the color itself unchanged. Tool property persistence retains each tool's size. M selects keyboard Move, I selects a composite-image eyedropper and brush selection returns to Paint. Move/Eyedropper reject brush size, opacity and line commands with a reason. Eyedropper clicks update the local selected color without painting. Ctrl-drag reduces numeric speed and slider pointer movement to one tenth; focused slider arrows use one-tenth numeric increments. Merely displaying a slider never rounds saved values.

Tests cover 1/100/6400% zoom, 37-degree rotation and mirror; one/ten-pixel moves, outside extents, feathered overlap, original-based repeats, grouping/net zero/saved checkpoints/stale history, empty/locked targets, old/native lock round trips, actual application key repeat/release, target/focus/modal changes, numeric/IME focus, brush limits, per-tool opacity and restart, unsupported modes, missing line endpoints, actual straight pixels with undo/redo, zero opacity and eyedropper invariance. Packaged smoke runs the same isolated CPU UI/pixel path; no physical input is implied.
